public static function stockOnHand(int $productId, int $locationId): int
{
    return (int) static::where('product_id', $productId)
        ->where('location_id', $locationId)
        ->sum('qty');
}

private function validateMovement(array $data)
{
    return validator($data, [
        'product_id' => ['required', 'integer', 'exists:products,id'],
        'location_id' => ['required', 'integer', 'exists:locations,id'],
        'type' => ['required', 'string', Rule::in(StockMovement::TYPES)],
        'qty' => ['required', 'integer', 'not_in:0'],
        'note' => ['nullable', 'string'],
    ])->validate();
}

private function normalizeQtyByType(string $type, int $qty): int
{
    return match ($type) {
        'IN' => abs($qty),
        'OUT' => -abs($qty),
        default => $qty,
    };
}

SAY WHILE TYPING (move the mouse)

  • For IN, I keep the positive amount using abs.
  • For OUT, I take the positive amount and put a minus in front. Shipping four is always saved as minus four, whether the caller sends four or minus four.
  • ADJUST is a correction, so I keep whatever sign was sent.

SAY

Now every outgoing quantity is stored as negative, which is exactly what stockOnHand expects. With the sign correct, I can check whether a shipment would take the stock below zero. That is the third helper.

private function hasSufficientStockForOut(int $productId, int $locationId, int $qty): array
{
    $stock = StockMovement::stockOnHand($productId, $locationId);

    return [
        'ok' => $stock + $qty >= 0,
        'stock' => $stock,
    ];
}

SAY WHILE TYPING (move the mouse)

  • Zero is allowed. Shipping all six of six leaves an empty warehouse, and that is valid.
  • I also return the current stock so a rejected request can explain itself.

public function store()
{
    $data = request()->only(self::FIELDS);
    $validated = $this->validateMovement($data);
    $validated['qty'] = $this->normalizeQtyByType($validated['type'], $validated['qty']);

    return DB::transaction(function () use ($validated) {
        if ($validated['type'] === 'OUT') {
            $result = $this->hasSufficientStockForOut(
                $validated['product_id'],
                $validated['location_id'],
                $validated['qty']
            );

            if (!$result['ok']) {
                return response()->json([
                    'message' => 'Insufficient stock',
                    'current_stock' => $result['stock'],
                    'requested_out' => abs($validated['qty']),
                ], 422);
            }
        }

        $movement = StockMovement::create($validated);

        return response()->json([
            'message' => 'Movement added successfully',
            'data' => $movement,
            'current_stock' => StockMovement::stockOnHand(
                $validated['product_id'],
                $validated['location_id']
            ),
        ], 201);
    });
}

SAY WHILE TYPING (move the mouse)

  • I read only the fields this endpoint accepts.
  • I run the input check, then I fix the sign. The sign is fixed before the stock check, so the stock check always sees a negative outgoing number.
  • The database work runs inside a transaction, so if a database error happens halfway, the changes roll back.
  • For OUT only, I call the stock check. If it fails, I return 422 with the available amount and the requested amount. This return happens before the save, so a rejected movement never reaches the database.
  • If the checks pass, I save the movement.
  • Then I compute the stock again, including the new row, and return both the row and the new balance with status 201, because a record was created.
